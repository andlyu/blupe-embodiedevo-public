# Physical YAM primitives

This is a physical transfer trial on YAM, using the frozen skills and lessons from simulation. The same four primitives are available: `get_instruction()`, `get_observation()`, `step(action)`, and `reset()`; reset is forbidden here. Call `get_instruction()` for the operator's task. Every submitted program executes from the robot's current measured state. An error does not undo movement.

Read the initial observations before planning. `vision.cam_head`, `cam_left_wrist`, and `cam_right_wrist` contain the actual top, left, and right RGB cameras. Their dimensions come from the physical relay, not RoboDojo. Camera metadata includes capture timestamps. There is no synthetic depth or object pose. The observation's calibration quality records its limitations.

`state.left_arm_joint_state` and `right_arm_joint_state` contain six encoder angles in radians. `left_ee_joint_state` and `right_ee_joint_state` are one-element **measured** gripper arrays: 0 closed, 1 open. `left_ee_pose` and `right_ee_pose` are `[x,y,z,qw,qx,qy,qz]` in metres, scalar-first quaternion, in **BluPe's base-midpoint frame, with Z=0 at arm base height**. These are YAM grasp frames. They are not RoboDojo's ARX world frame. Never reuse absolute simulator coordinates, ARX home joints, model offsets or gripper geometry as physical facts. Adapt in writable `submission/`; keep frozen knowledge unchanged.

`step(action)` takes exactly four keys. Joint mode uses `left_arm_joint_state`, `right_arm_joint_state`, `left_ee_joint_state`, `right_ee_joint_state`. EE mode replaces the two arm-joint keys with `left_ee_pose`, `right_ee_pose`. Both arms must be explicit. Hold the other arm at measured state. All values must be finite with exact shapes; quaternions must be unit length and grippers in [0,1]. The host solves EE targets against the pinned local YAM model, verifies its FK against the published selected-station calibration, checks predictive contacts and interpolates complete paired paths. It never clamps a malformed command into a different motion.

The existing BluPe controller and gateway own the actual lease, validation, packet dispatch, ordered progress and settled measured completion. Packets execute at **10 Hz**. One `step` may require several waypoints to maintain the existing motion increment bound; `native_steps_used` counts physical waypoints. HTTP, image capture, planning and settling add wall time. The host returns new measured joints, grippers and camera images after completion, never commanded target values as feedback.

There is no automatic physical task-success checker. The primitive success flag does not establish success. Finish when the task appears complete or no further valid progress is possible; the operator reviews recorded evidence afterward. An agent's completion claim is not a scored result. The physical run, failures, interventions, original submitted source and frozen knowledge lineage are retained. Physical actions are **never replayed** for recording. On an uncertain connection, query status rather than resubmitting. Stop or budget exhaustion ends this trial; it does not start another.
